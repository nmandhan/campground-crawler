Rules, all load-bearing:
- **Any** fetch failure or **any** top-level parse failure across the three files returns
  `{ ok: false }`. Rationale: UI-SPEC.md defines exactly one failure presentation
  (`Unable to load dashboard data`) and no per-section fallback copy. Rendering two real
  sections plus a silently-empty third would be dishonest. A malformed *individual* runs.json
  entry is different — `parseRunLog` already skips those, and the count surfaces as
  `skippedRuns`.
- The `{ ok: false }` variant carries **no fields at all**. The `error` strings from
  `FetchResult`/`ParseResult` must not be copied into the model, because everything in the model
  is rendered to a public page (threat T-03-13).
- `dataAsOfLabel`: `const last = latestRun(runs)`; when `last === null` → `null`; otherwise
  `` `${COPY.dataAsOfPrefix}${formatAbsolute(last.startedAt)} (${formatRelativeTime(last.startedAt, now)})` ``.
  The timestamp comes from the payload, never from `now` (RESEARCH.md Pitfall 1 — the page must
  be honest about CDN lag).
- Call each derive function exactly once, passing the same `now`, so every relative timestamp on
  the page refers to one consistent moment.
- Order of derivation is irrelevant, but the returned arrays must be passed through untouched —
  no re-sorting, no slicing, no formatting in this module beyond `dataAsOfLabel`.
