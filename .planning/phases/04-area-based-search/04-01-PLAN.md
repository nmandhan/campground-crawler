<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| RIDB API -> poller | Untrusted third-party JSON crosses into the process; RIDB may change shape without notice |
| `watches.json` -> outbound URL | Developer-authored area names and `recAreaId` values are interpolated into a RIDB request |
| Error text -> logs / `runs.json` (public repo) | `RIDB_API_KEY` must never reach a committed artifact |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | `RidbRecAreaSearchSchema` / `RidbRecAreaFacilitiesSchema` | mitigate | Every RecArea response is `safeParse`d before any field access; unknown/extra keys are dropped by zod's default strip behavior, and a shape change fails loudly as `ResponseSchemaError` rather than producing `undefined` field reads |
| T-04-03 | Information Disclosure | `scripts/capture-recarea-fixtures.ts` | mitigate | `RIDB_API_KEY` is sent only as the `apikey` HTTP header, never a query param, so it can never appear in a `HttpError`'s `url` field or in a captured fixture. Acceptance criteria assert zero `searchParams.set('apikey'` occurrences |
| T-04-04 | Tampering | Search URL construction | mitigate | Area name goes through `url.searchParams.set('query', areaName)` — `URLSearchParams` percent-encodes it; no string concatenation into the URL |
| T-04-05 | Tampering | Facilities URL path segment | mitigate | `recAreaId` is wrapped in `encodeURIComponent(String(recAreaId))` before being placed in the path, preventing `../` path traversal into a different RIDB resource |
| T-04-07 | Information Disclosure | Committed fixtures (public repo) | accept | Captured RecArea/facility data is public federal recreation data with no PII or secrets; the capture script never writes request headers into the fixture, only the response body |
</threat_model>
