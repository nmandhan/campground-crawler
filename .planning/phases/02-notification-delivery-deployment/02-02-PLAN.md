`RunDeps.sendNotification` dependency, called exactly once per cycle with the post-dedup

deployment-agnostic per ARCHITECTURE.md Anti-Pattern 2: the send belongs inside `run()`, not

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `run()` → notification I/O | New outbound side effect added to a previously network-scoped-to-Recreation.gov pipeline |
| Notification failure → process exit code | A third-party outage must not be able to change the operational signal that means "polling is broken" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Denial of Service | `run()` notification call site in `src/run.ts` | mitigate | The `await sendNotification(...)` is wrapped in try/catch that logs via `describeFailure` and continues; `sendDigestEmail` itself also never throws (T-02-04). A Resend outage cannot abort a poll cycle or prevent `store.save()`, which already ran earlier at line 82. |
| T-02-08 | Repudiation / Tampering | Conflation of notification failure with watch failure | mitigate | Notification errors are logged as `notification failed: ...` and explicitly excluded from `RunSummary.failed`; enforced by the acceptance criterion that `git diff src/cli.ts` and `git diff src/types.ts` are empty and by the "rejecting notifier leaves `summary.failed` empty" test. |
| T-02-09 | Information Disclosure | Notification payload contents in a public-repo Actions log | mitigate | `run.ts` logs only `describeFailure(err)` (contractually header/apikey-free per `src/errors.ts`); the match details themselves go to the email body, and the existing per-watch `OK` log line already prints site labels — no new disclosure surface beyond Phase 1's accepted logging. |
| T-02-10 | Spoofing | A caller injecting a hostile `sendNotification` via `RunDeps` | accept | `RunDeps` is an in-process test seam in a single-user tool; anyone who can pass deps already controls the process. No mitigation warranted. |
</threat_model>
