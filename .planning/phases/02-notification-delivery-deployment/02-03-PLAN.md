    create it) with exactly this content:

    ```yaml
    name: Poll campsite availability

    # D-08: 5-minute cadence. GitHub's scheduler is best-effort and may skew or skip
    # runs under load — that is acceptable here; dedup state makes a skipped cycle
    # harmless and a doubled cycle idempotent.
    on:
      schedule:
        - cron: '*/5 * * * *'
      workflow_dispatch: {}

    # D-10: queue overlapping runs, never cancel one mid-flight. A cancelled run could
    # be interrupted between the email send and the state commit, producing a duplicate
    # alert next cycle. Do NOT change this to `true`.
    concurrency:
      group: poller
      cancel-in-progress: false

    # Least privilege: only what the state commit-back push needs. Public repos default
    # GITHUB_TOKEN to read-only for contents, which would make the push fail with 403.
    permissions:
      contents: write

    jobs:
      poll:
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v7

          - uses: actions/setup-node@v7
            with:
              node-version: '22'
              cache: npm

          - run: npm ci

          - name: Run poller
            id: poll
            env:
              RESEND_API_KEY: ${{ secrets.RESEND_API_KEY }}
              NOTIFY_EMAIL: ${{ secrets.NOTIFY_EMAIL }}
              NOTIFY_FROM: ${{ secrets.NOTIFY_FROM }}
              RIDB_API_KEY: ${{ secrets.RIDB_API_KEY }}
            run: npm start

          - name: Commit dedup state if it changed
            if: always()
            run: |
              set -euo pipefail
              if [ -z "$(git status --porcelain -- state.json)" ]; then
                echo "state.json unchanged — skipping commit"
                exit 0
              fi
              git config user.name "github-actions[bot]"
              git config user.email "41898282+github-actions[bot]@users.noreply.github.com"
              git add state.json
              git commit -m "chore: update dedup state [skip ci]"
              git push
    ```

    Every element above is load-bearing — do not "simplify" any of it:
    - `workflow_dispatch: {}` enables the manual smoke test in plan 02-04.
    - `node-version: '22'` pins the Node 22.x LTS target from CLAUDE.md, independent of
      whatever Node version the runner image defaults to.
    - `git status --porcelain -- state.json` (NOT `git diff --quiet`): `git diff` reports no
      change for an untracked file, which would silently disable commit-back if the tracking
      from task 1 ever regressed. `git status --porcelain` catches untracked AND modified.
    - `if: always()` on the commit step: when a watch fails, `npm start` exits 1, but state for
      the watches that DID succeed must still be persisted or those sites re-alert next cycle.
      The job still reports failure because the `Run poller` step already failed (D-11).
    - No `|| true` anywhere: a failed `git push` (e.g. a 403 from missing permissions) must
      fail the job loudly rather than silently dropping state forever (RESEARCH Pitfall 2).
    - `set -euo pipefail` makes the push failure actually propagate.
    - Secrets are injected via `env:` only. NEVER add an `echo "$RESEND_API_KEY"`, a
      `printenv`, or any debug step that prints the environment.

    Note on `RIDB_API_KEY`: D-03 scopes secrets to `NOTIFY_EMAIL` + `RESEND_API_KEY`, but
    Phase 1's 01-04-SUMMARY carried forward that RIDB returns HTTP 401 without a key and
    explicitly recommended adding it as a GitHub secret. It is injected here as an OPTIONAL
    secret — an unset secret expands to an empty string, and `src/config/watches.ts:124`
    already treats an empty value as absent. This satisfies OPS-03 ("API keys stored as
    secrets") without moving any non-secret config out of `watches.json` (D-02/D-03 intent
    preserved).

    Validate the YAML parses before committing:
    `node -e "const {execSync}=require('child_process')"` is not sufficient — instead run
    `npx --yes js-yaml .github/workflows/poll.yml > /dev/null` (or `python3 -c "import yaml,sys; yaml.safe_load(open('.github/workflows/poll.yml'))"`).

| T-02-13 | Elevation of Privilege | Over-permissioned `GITHUB_TOKEN` | mitigate | Explicit workflow-level `permissions: contents: write` — the single scope the commit-back push needs. No `write-all`, no `id-token`, no `packages`. |
