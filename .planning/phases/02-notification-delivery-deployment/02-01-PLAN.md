       const MAX_FIELD_LENGTH = 200;

       /** Collapse CR/LF and runs of whitespace, trim, and truncate. Prevents a hostile or
        *  malformed upstream field from injecting extra lines into the subject (email header
        *  injection) or forging structure in the plain-text body (threat T-02-02).

       function sanitize(value: string): string {
         const flat = String(value ?? '').replace(/[\r\n\t]+/g, ' ').replace(/ {2,}/g, ' ').trim();
         return flat.length > MAX_FIELD_LENGTH ? `${flat.slice(0, MAX_FIELD_LENGTH)}…` : flat;

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Recreation.gov API → app | `facilityName`, `siteLabel`, `loop` in `MatchedSlot` originate from an undocumented third-party JSON API and are interpolated into email subject/body |
| App → Resend API | `RESEND_API_KEY` crosses this boundary; the request payload contains the recipient address |
| App → logs | This repo becomes PUBLIC (D-01), so every logged line lands in world-readable GitHub Actions run logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | `sendDigestEmail` error/success logging in `src/notify/email.ts` | mitigate | Log only `error.name`/`error.message` or `describeFailure(err)`; never interpolate `apiKey`, `payload`, or the recipient. Enforced by the `! grep -q '\${apiKey}'` and recipient-logging acceptance criteria plus a test asserting `re_test_supersecret` never appears in a log line. |
| T-02-02 | Tampering / Spoofing | `buildSubject` / `buildBody` interpolation of upstream API strings | mitigate | `sanitize()` strips CR/LF/tab and collapses whitespace on every interpolated upstream field, blocking email header injection via the subject and forged structure in the plain-text body; 200-char truncation caps abuse. Covered by the injected-newline test cases. |
| T-02-03 | Spoofing | `bookingUrl` rendered into the email as a clickable link | mitigate | `safeBookingUrl()` allowlists the `https://www.recreation.gov/` prefix; anything else renders `(booking link unavailable)` rather than pasting an attacker-controlled URL into the user's inbox. |
| T-02-04 | Denial of Service | Resend outage / invalid key crashing the poll cycle | mitigate | `sendDigestEmail` never throws — every failure path returns after a single logged line, so `run()` and the schedule survive an email-provider outage (D-11/D-12 boundary preserved). |
| T-02-05 | Elevation of Privilege | Resend API key blast radius if compromised | transfer | Key scope is a Resend-dashboard account setting, not code; plan 02-04's setup checkpoint instructs the user to create a send-only restricted key. |
| T-02-06 | Repudiation | Silent notification loss (email never sent, nothing recorded) | accept | Single-user tool; the `email sent: N new matches` info line plus the missing-credential error lines in the Actions log give sufficient traceability. A delivery-receipt/audit store is disproportionate for v1. |
</threat_model>
