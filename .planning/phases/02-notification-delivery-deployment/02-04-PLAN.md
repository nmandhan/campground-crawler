<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Private repo → public repo | The visibility flip in task 2 makes all history permanently world-readable; a secret already in history becomes unrecoverable |
| User → GitHub Secrets store | Credentials are entered by hand and could be pasted into the wrong field (e.g. a repo *variable* instead of a *secret*) |
| Resend account → the world | An over-scoped API key grants more than send capability if leaked |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Information Disclosure | Making the repo public with a secret already in git history | mitigate | Task 1 runs four independent history/working-tree scans (`git log --all -p` for `re_` and `RIDB_API_KEY=`, `.env` commit history, `git grep`) and blocks task 2 on a clean result; task 2's step 3 explicitly instructs the user to flip visibility only after the audit passes. |
| T-02-19 | Elevation of Privilege | Resend key with Full access instead of Sending access | mitigate | Task 2 step 1 instructs "Sending access (NOT Full access)"; task 3 step 2 confirms no key value appears in the public run log. |
| T-02-20 | Information Disclosure | Credential entered as a repo Variable (plaintext, world-readable on a public repo) rather than a Secret | mitigate | Task 2 names the exact path "Secrets and variables -> Actions -> **New repository secret**"; task 3 step 2 verifies GitHub redaction behavior in the log. |
| T-02-21 | Spoofing / Denial of Service | Alert email silently filtered to spam, defeating the core value prop | mitigate | Task 3 step 4 explicitly requires checking the spam folder; task 4 records the outcome and adds a caveat if the shared sender was used, so the deliverability risk is documented rather than assumed away. |
| T-02-22 | Repudiation | A scheduled run that never fires and is never noticed | mitigate | Task 3 step 6 requires observing an automatically-triggered (non-manual) run within 20 minutes; D-11's non-zero exit on watch failure surfaces subsequent breakage as a red X in the Actions tab. |
</threat_model>
