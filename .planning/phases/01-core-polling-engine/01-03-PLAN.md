**`src/matcher/dates.ts`** — UTC-safe date helpers. Local-time `new Date('2026-09-04')` arithmetic silently shifts by a day in negative-offset timezones, which would make the matcher check the wrong nights:
```typescript
/** Add N days to a YYYY-MM-DD string, computed in UTC. */
export function addDays(isoDate: string, days: number): string {
  const [y, m, d] = isoDate.split('-').map(Number);
  const dt = new Date(Date.UTC(y!, m! - 1, d!));
  dt.setUTCDate(dt.getUTCDate() + days);
  return dt.toISOString().slice(0, 10);
}

/** Nights required for a stay: [start, end) — `end` is the exclusive checkout date (D-03). */
export function nightsInRange(start: string, end: string): string[] {
  const out: string[] = [];
  for (let cur = start; cur < end; cur = addDays(cur, 1)) out.push(cur);
  return out;
}
```
(The `cur < end` string comparison is valid because YYYY-MM-DD sorts lexicographically. A reversed range yields `[]` immediately.)

**`src/matcher/match.ts`** — the pure matcher. No I/O, no imports from `src/recreation-gov/` or `src/state/`:
```typescript
export function siteTypeMatches(watchType: SiteType, slotType: ResolvedSiteType): boolean {
  return watchType === 'any' ? true : watchType === slotType;
}

export function matchWatch(slots: AvailabilitySlot[], watch: ResolvedWatch): MatchedSlot[];
```
`matchWatch` algorithm:
1. `const nights = nightsInRange(watch.dateRange.start, watch.dateRange.end)`. If `nights.length === 0`, return `[]`.
2. Group `slots` by `campsiteId` into a `Map<string, Map<string /*date*/, AvailabilitySlot>>`.
3. For each campsite, take any one slot as the representative for metadata (`siteLabel`, `loop`, `campsiteType`, `siteType`).
4. Skip the campsite unless `siteTypeMatches(watch.siteType, representative.siteType)` (D-04).
5. Require that EVERY night in `nights` has a slot for that campsite AND that slot's `available === true`. A missing date is a failed match — absence of data is never treated as availability.
6. On success push a `MatchedSlot` with `watchId: watch.id`, `facilityId: watch.facilityId`, `facilityName: watch.facilityName`, `startDate: watch.dateRange.start`, `endDate: watch.dateRange.end`, `bookingUrl: buildBookingUrl(campsiteId)`.
7. Return matches sorted by `campsiteId` (string sort).

Add a comment noting D-03 explicitly: this is "the whole range as one continuous bookable stay", NOT "any single open night in the range".

Create `src/state/fileStore.ts` implementing the `StateStore` interface from `src/state/store.ts`.

```typescript
import { readFile, writeFile, rename, mkdir } from 'node:fs/promises';
import { dirname } from 'node:path';
import type { StateStore, StateEntry, StateFile } from './store.js';

export const DEFAULT_STATE_PATH = 'state.json';

export interface FileStateStoreOptions {
  path?: string;                                  // default DEFAULT_STATE_PATH
  logger?: { warn: (msg: string) => void };       // default console
}

export class FileStateStore implements StateStore {
  constructor(opts?: FileStateStoreOptions);
  load(): Promise<void>;
  has(key: string): boolean;
  get(key: string): StateEntry | undefined;
  markNotified(key: string, at?: Date): void;
  save(): Promise<void>;
}

export function createFileStateStore(opts?: FileStateStoreOptions): FileStateStore;
```

Implementation specifics:
- Internal state: `private entries: Map<string, StateEntry>`.
- `load()`: `readFile(path, 'utf8')` in a try/catch. On `ENOENT` -> empty map, no warning (normal first run). On any parse/shape failure -> empty map + `logger.warn(\`state file at ${path} was unreadable (${reason}); starting from empty state — a duplicate alert is possible this cycle\`)`. Validate the parsed object structurally: it must be a non-null object with a `version === 1` and an `entries` object whose values each have a string `lastNotifiedAt`; drop individual malformed entries rather than the whole file where that is unambiguous.
- `markNotified(key, at = new Date())`: `this.entries.set(key, { lastNotifiedAt: at.toISOString() })`. Store the timestamp, never a boolean (D-09 — this is what lets NOTF-04 cooldown ship later with no migration).
- `save()`: build `const file: StateFile = { version: 1, entries: Object.fromEntries([...this.entries].sort(([a],[b]) => a < b ? -1 : a > b ? 1 : 0)) }` — sorting keys keeps the committed diff stable. Then `await mkdir(dirname(path), { recursive: true })`, `await writeFile(tmp, JSON.stringify(file, null, 2) + '\n', 'utf8')`, `await rename(tmp, path)` where `tmp = path + '.tmp'`.
- This class is the ONLY place in the codebase that reads or writes the state file. Do not add a KV implementation (explicitly deferred in CONTEXT.md).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `state.json` on disk -> app | A file that can be corrupted by an interrupted write, hand-edited, or (in Phase 2) merged by git; its contents drive whether the user is alerted |
| `AvailabilitySlot[]` from the API adapter -> matcher | Already zod-validated upstream, but semantically untrusted (a status-vocabulary change flips availability meaning) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Denial of Service | `FileStateStore.load()` | mitigate | A missing, truncated, or malformed `state.json` yields an empty in-memory store plus a logged warning instead of a thrown exception — the poll cycle continues. Worst case is one duplicate alert, which is strictly better than the poller going dark. |
| T-03-02 | Tampering | `FileStateStore.save()` | mitigate | Atomic write via `writeFile(path + '.tmp')` + `rename(tmp, path)` — a process killed mid-save leaves the previous complete file intact rather than a truncated one that would be discarded on next load (causing spurious re-alerts). |
| T-03-03 | Spoofing | dedup key construction | mitigate | Keys are always built via `dedupKey(watchId, campsiteId, startDate, endDate)`; tests assert `watch-a` and `watch-b` entries for identical site/dates are independent, so no watch can consume or suppress another watch's state (WATCH-02). |
| T-03-04 | Information Disclosure | state file contents | accept | `state.json` contains only watch ids, campsite ids, dates, and timestamps — no credentials, no PII. `.gitignore` (plan 01) keeps local run state out of git; Phase 2 revisits whether the deployed state file is committed. |
| T-03-05 | Tampering | `matchWatch` availability semantics | mitigate | Missing nightly data is treated as NOT available (never as availability), and every night in [start, end) must be explicitly `available: true` — an upstream field rename degrades to false negatives (silence) rather than false positives (alerting on unbookable sites). |
</threat_model>
