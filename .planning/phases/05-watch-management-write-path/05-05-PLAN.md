**`handleDelete`:**
```tsx
if (!pendingDelete) return;
setBusy(true); setError(null);
try {
  const res = await fetch(`/api/watches/${encodeURIComponent(pendingDelete.id)}`, { method: 'DELETE' });
  const body = (await res.json().catch(() => ({}))) as { ok?: boolean; error?: string };
  if (res.ok && body.ok) {
    setWatches((prev) => prev.filter((w) => w.id !== pendingDelete.id));
    setToast(COPY.deletedToast);
  } else if (res.status === 401) {
    setUnlocked(false);                       // the ~30d cookie expired mid-session
    setError(COPY.unlockHeading);
  } else {
    setError(COPY.saveFailed.replace('{reason}', body.error ?? ''));
  }
} catch {
  setError(COPY.saveFailed.replace('{reason}', ''));
} finally {
  setBusy(false); setPendingDelete(null);
}
```
`encodeURIComponent` on the id is required — ids are user-authored strings and must not be able to
escape their path segment.

A 401 resets `unlocked` to `false` so the unlock prompt reappears rather than the user retrying a
dead session forever (D-03's 30-day cookie does eventually expire).

**Toast (D-12)** — a non-modal fixed banner that must not block the page underneath:
```tsx
{toast ? <div className="toast" role="status" onClick={() => setToast(null)}>{toast}</div> : null}
```
Auto-dismiss after ~4s with `useEffect(() => { if (!toast) return; const t = setTimeout(() => setToast(null), 4000); return () => clearTimeout(t); }, [toast])`. The cleanup is required — without it a second
toast inside 4s would be cancelled by the first one's stale timer.

Export `WatchManager` as a named export. Every user-visible string comes from `COPY` — zero inline
literals except the `×` glyph and the `·` separator.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server Component → client component props | `unlocked` crosses here; the cookie value itself must not |
| User-authored watch id → URL path segment | `/api/watches/{id}` interpolation |
| Committed `watches.json` → rendered DOM | Data the dashboard does not control the shape of |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-21 | Information Disclosure | `unlocked` prop | mitigate | Only the boolean crosses the server/client boundary — the cookie value and `DASHBOARD_PASSPHRASE` never appear in the serialized RSC payload |
| T-05-22 | Tampering | watch id in the DELETE URL | mitigate | `encodeURIComponent(pendingDelete.id)` so an id containing `/` or `..` cannot escape its path segment; the server additionally matches ids by exact string equality, never by path |
| T-05-23 | Tampering | XSS from `watches.json` content | mitigate | Watch fields render as React text nodes (auto-escaped); no `dangerouslySetInnerHTML`; the repo is public but only the PAT holder and the poller can write to it |
| T-05-24 | Elevation of Privilege | client-side `unlocked` state | accept | Flipping `unlocked` in devtools only reveals buttons; every request they fire is still rejected by `proxy.ts` plus the handler's own `requireSession()`. The client flag is an affordance, never an authorization decision |
| T-05-03 | Denial of Service | deleting the last watch | mitigate | Server-side 409 (plan 05-03); the UI surfaces the returned message verbatim via `COPY.saveFailed` rather than optimistically removing the row |
</threat_model>
