# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — plain CSS in `dashboard/app/globals.css`, no Tailwind/shadcn |
| Preset | not applicable |
| Component library | none — plain Server Components, zero client JS (no interactivity per RESEARCH.md D-03/D-08 architecture) |
| Icon library | none — status is conveyed via text labels + color, not icons (avoids an unnecessary dependency on a single-page, no-interactivity dashboard) |
| Font | system font stack: `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif` — no custom webfont load for a low-traffic internal tool |

**Rationale:** RESEARCH.md's scaffold command explicitly passes `--no-tailwind`, and the "Recommended Project Structure" notes "minimal/no styling framework needed." This phase is a single SSR page with three static sections (per-watch status, run timeline, active matches) and no forms, no client interactivity, no design-system reuse across multiple future pages — shadcn's Radix/Tailwind stack would be disproportionate. Plain, scoped CSS keeps `dashboard/` dependency-light and consistent with the project's overall minimal-dependency philosophy (CLAUDE.md: reuse `zod`, no new frameworks without cause).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Badge internal padding, inline gaps between label and value |
| sm | 8px | Compact spacing between table rows, list items |
| md | 16px | Default spacing between elements within a section |
| lg | 24px | Padding inside section cards |
| xl | 32px | Gap between the three major sections (Active Matches / Per-Watch Status / Run Timeline) |
| 2xl | 48px | Space between page header and first section |
| 3xl | 64px | Top/bottom page margin on desktop viewports |

Exceptions: none — this is a read-only, non-touch, desktop-first page (no mobile touch-target sizing concerns), so the standard 8-point scale applies without modification.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Meta/timestamp | 14px | 400 | 1.5 |
| Body (table/list content, watch details) | 16px | 400 | 1.5 |
| Section heading (Active Matches / Per-Watch Status / Run Timeline) | 20px | 600 | 1.2 |
| Page title ("Campground Crawler — Status") | 28px | 600 | 1.2 |

Exactly 4 sizes, 2 weights (400 regular, 600 semibold) — no other sizes/weights permitted.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background |
| Secondary (30%) | `#F1F3F5` | Section card backgrounds, table row striping, borders/dividers (`#E2E5E9`) |
| Accent (10%) | `#2563EB` | Reserved exclusively for: Recreation.gov booking links in the Active Matches section, and the page title/section-heading text |
| Destructive | `#DC2626` | Reserved exclusively for: FAILED run-outcome badges/text |

Accent reserved for: booking links (`Book on Recreation.gov →`) and page/section heading text only — never used for body text, table rows, or decorative elements.

**Additional semantic status colors** (dashboard-specific, outside the 60/30/10 surface split — used only inside status badges):

| Status | Color | Usage |
|--------|-------|-------|
| MATCH | `#16A34A` (green) | Badge background/text for a MATCH outcome, in Per-Watch Status and Run Timeline sections only |
| NO_MATCH | `#6B7280` (neutral gray) | Badge background/text for a NO_MATCH outcome |
| FAILED | `#DC2626` (same as Destructive) | Badge background/text for a FAILED outcome |

These three colors are mutually exclusive per badge instance (one outcome = one color) and never combined with the Accent blue.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (per active match) | `Book on Recreation.gov →` (links directly to the site's Recreation.gov booking page) |
| Empty state heading (no active matches) | `No active matches yet` |
| Empty state body (no active matches) | `None of your watches have found an open site yet. This page updates automatically after each poll cycle — check back in a few minutes.` |
| Empty state heading (no run history yet) | `No poll runs recorded yet` |
| Empty state body (no run history yet) | `The poller hasn't completed a cycle since this dashboard went live. Check back shortly.` |
| Error state (GitHub fetch failure) | `Unable to load dashboard data` — body: `Couldn't fetch the latest data from GitHub just now. This is usually temporary — try refreshing in a minute.` |
| Destructive confirmation | Not applicable — this phase has no destructive actions (read-only dashboard, no delete/edit/write operations exposed to the browser) |
| Data freshness label | `Data as of {runs.json latest timestamp}` — sourced from the JSON payload itself, not page-render time (per RESEARCH.md Pitfall 1, to stay honest about CDN/cache lag) |

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|--------------|
| shadcn official | none — shadcn not initialized this phase | not applicable |

No component registry is used. `Tool: none` per Design System section above — the shadcn initialization gate was intentionally declined for this phase (see rationale above): a single static SSR page with zero client interactivity does not warrant introducing shadcn/Tailwind/Radix as a new dependency surface. If a future phase adds interactive dashboard features (filters, live refresh controls, forms), re-run the shadcn gate at that time.
