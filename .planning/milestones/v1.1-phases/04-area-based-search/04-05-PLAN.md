      const collected: AreaFacility[] = [];

      for (const area of watch.areas) {                       // D-10: area-list order
        const cacheKey =
          area.recAreaId !== undefined
            ? `id:${area.recAreaId}`
            : `name:${area.name.trim().toLowerCase()}`;

        let pending = areaCache.get(cacheKey);
        if (!pending) {
          ridbCallCount += area.recAreaId !== undefined ? 1 : 2;
          pending = (async () => {
            let recAreaId = area.recAreaId;
            if (recAreaId === undefined) {
              // D-02/D-03: auto-pick RIDB's top match, surface the rest, never fail closed.
              const match = await resolveAreaFn(area.name, opts);
              recAreaId = match.recAreaId;
              logger.info(`resolved area "${area.name}" -> recArea ${match.recAreaId} (${match.recAreaName})`);
              if (match.alternatives.length > 0) {
                logger.warn(
                  `  other RIDB areas for "${area.name}": ${match.alternatives.join(', ')} — ` +
                    `set "recAreaId" on this area in watches.json if this resolved to the wrong area`
                );
              }
            }
            return listFacilitiesFn(recAreaId, opts);
          })();
          areaCache.set(cacheKey, pending);
        }

        for (const f of await pending) {                      // D-09: RIDB's order, never re-sorted
          if (seen.has(f.facilityId)) continue;               // one campground reachable from two areas counts once
          seen.add(f.facilityId);
          collected.push(f);
        }

      if (collected.length === 0) {
        throw new Error(
          `no reservable campgrounds found across ${watch.areas.length} area(s) for watch "${watch.id}"`
        );
      }

      const kept = collected.slice(0, AREA_FACILITY_CAP);     // D-07: cap AFTER filter+dedup, BEFORE polling
      if (collected.length > kept.length) {
        truncations.push({ watchId: watch.id, requested: collected.length, kept: kept.length });
        logger.warn(
          `watch "${watch.id}" resolved ${collected.length} campgrounds — showing ${kept.length} of ` +
            `${collected.length} (capped at AREA_FACILITY_CAP=${AREA_FACILITY_CAP})`

      }

      for (const f of kept) {
        resolved.push({
          id: watch.id,
          facilityId: f.facilityId,
          facilityName: f.facilityName,
          facilityType: f.facilityType,
          dateRange: watch.dateRange,
          siteType: watch.siteType,

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `watches.json` -> RIDB request volume | A config author (or a future dashboard write path) controls how many areas a watch lists; each area fans out to an unbounded facility count |
| RIDB facility list -> availability polling loop | Every surviving facility becomes a sequence of live `recreation.gov` availability requests |
| One watch's failure -> the whole poll run | The run must always complete and always write `runs.json`, or the dashboard goes stale |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02 | Denial of Service | `resolveWatches` area branch | mitigate | `AREA_FACILITY_CAP = 20` applied via `collected.slice(0, AREA_FACILITY_CAP)` AFTER filtering and dedup and BEFORE any availability polling. Shared across all areas in the watch (D-10), so listing 50 areas still yields 20 facilities. This resolver is the only enforcement point in the phase — there is no UI to also gate it. Asserted by a test feeding 36 facilities and expecting exactly 20 |
| T-04-18 | Denial of Service | Duplicate area / duplicate facility | mitigate | `areaCache` memoizes the resolved facility list per unique area per run, so N watches naming the same area cost one pair of RIDB calls; `seen: Set<number>` dedupes a facility reachable from two areas so it is polled once. Both asserted by call-counting tests |
| T-04-06 | Denial of Service | One bad area name | mitigate | The existing per-watch `try/catch` is preserved unchanged, so a `RecAreaNotFoundError` (or a zero-facility area) becomes one `failures` entry and every other watch still resolves. Asserted by a test with one failing and one healthy watch |
| T-04-19 | Denial of Service | RIDB 50 req/min burst | accept | Per RESEARCH.md Pitfall 1, a realistic single-user config is ~35 calls fired in a few seconds, comfortably inside a sliding-minute window, and `retryWithBackoff` already recovers a 429. Rather than build a premature TTL cache, the risk is made visible: `logger.info('RIDB resolution calls this run: N')` lands the count in every run's log so a future scale-up is observable |
| T-04-09 | Tampering | `recAreaId` override reaching a URL path | mitigate | Defense in depth already in place: `AreaWatchSchema` (04-02) rejects non-positive-integer values at config load, and `listAreaFacilities` (04-03) applies `encodeURIComponent` to the path segment. This plan adds no new URL construction |
| T-04-20 | Information Disclosure | Failure reasons written to `runs.json` in a public repo | mitigate | All failure text flows through `describeFailure`, which is documented and tested to never emit request headers or an `apikey`; the zero-facility `throw new Error(...)` message contains only the watch id and the area count, no credential and no URL |
