```tsx
'use client';

/** Create/edit watch modal (MGMT-02/MGMT-03, D-04/D-05).
 *
 *  A native <dialog>, not a route: editing a watch is a small focused decision, and a modal keeps
 *  the list it belongs to visible behind it (D-04). <dialog>.showModal() gives focus trapping and
 *  Escape-to-close with zero JS and zero dependencies, which is why the UI-SPEC picked it over a
 *  hand-rolled overlay.
 *
 *  ONE form for both union members (D-05). The Facility/Area toggle swaps ONLY the location
 *  section; the date-range and site-type fields keep their position when it flips, so the toggle
 *  never feels like it navigated somewhere else.
 *
 *  This component owns draft state and validation only. It does not fetch — `onSubmit` hands the
 *  assembled Watch up to watch-manager, which owns the POST/PATCH and the server's verdict.
 */
import { useEffect, useRef, useState } from 'react';
import { COPY } from '@/lib/copy';
import type { Watch, SiteType } from '@/lib/types';
import { AreaTypeahead, type AreaChip } from './area-typeahead';
import { AreaPreview } from './area-preview';

export function WatchForm({
  open,
  initial,
  submitting,
  serverError,
  onSubmit,
  onCancel,
}: {
  open: boolean;
  /** null = create, a Watch = edit that watch */
  initial: Watch | null;
  submitting: boolean;
  serverError: string | null;
  onSubmit: (watch: Watch) => void;
  onCancel: () => void;
}) { /* ... */ }
```

**Draft state** (flat, so the toggle never loses the other mode's input):
`kind: 'facility' | 'area'`, `id: string`, `parkName: string`, `areas: AreaChip[]`,
`start: string`, `end: string`, `siteType: SiteType`, `errors: Record<string, string>`.

Seed it from `initial` in a `useEffect` keyed on `[open, initial]`:
- `initial === null` → `kind: 'facility'`, all fields empty, `siteType: 'any'`, `areas: []`
- `initial.type === 'facility'` → `kind: 'facility'`, `id`, `parkName`, dates, `siteType`, `areas: []`
- `initial.type === 'area'` → `kind: 'area'`, `id`, `areas: initial.areas`, dates, `siteType`, `parkName: ''`

Re-seeding on open is required — reusing one mounted dialog for successive edits would otherwise
show the previous watch's values.

**Dialog control**, mirroring `watch-manager.tsx`'s existing pattern:
```tsx
const ref = useRef<HTMLDialogElement>(null);
useEffect(() => { if (open) ref.current?.showModal(); else ref.current?.close(); }, [open]);
```
Put `onClose={onCancel}` on the `<dialog>` so Escape routes through the same cancel path as the
Discard button, instead of leaving the parent thinking the modal is still open.

**Markup:**
```tsx
<dialog className="dialog" ref={ref} onClose={onCancel}>
  <h3 className="dialog-heading">{initial ? COPY.modalHeadingEdit : COPY.modalHeadingCreate}</h3>
  <form onSubmit={handleSubmit}>
    <div className="form-sections">

      {/* 1. Type toggle (D-05) */}
      <div className="toggle" role="group" aria-label={COPY.modalHeadingCreate}>
        <button type="button"
          className={kind === 'facility' ? 'btn toggle-option toggle-option--active' : 'btn toggle-option'}
          aria-pressed={kind === 'facility'}
          onClick={() => setKind('facility')}>{COPY.toggleFacility}</button>
        <button type="button"
          className={kind === 'area' ? 'btn toggle-option toggle-option--active' : 'btn toggle-option'}
          aria-pressed={kind === 'area'}
          onClick={() => setKind('area')}>{COPY.toggleArea}</button>
      </div>

      {/* 2. Location section — the ONLY part the toggle swaps */}
      {kind === 'facility' ? (

    </div>
  </form>
</dialog>
```

**Field specifics:**
- `id`: `<input className="field-input" type="text">`, label `Watch ID`. When editing, keep it
  editable — the PATCH handler supports renaming and rejects a collision with 409.
- `parkName`: `<input className="field-input" type="text">`, label `Campground name`.
- `start` / `end`: `<input className="field-input" type="date">` — the native date input already emits
  `YYYY-MM-DD`, which is exactly the format `StrictWatchSchema`'s regex requires, so no formatting
  or `new Date()` round-tripping is needed (and `new Date()` would shift the value across timezones).
- `siteType`: `<select className="field-input">` with options `any` / `tent` / `rv` / `group`,
  labelled from a local `Record<SiteType, string>` mapping to `Any site type` / `Tent` / `RV` / `Group`
  (the same labels `lib/format-watch.ts` uses).
- Every input carries a `<label className="field-label" htmlFor=…>` and a matching `id`.

**`validate()`** — mirrors `StrictWatchSchema` so the user sees the problem before a round trip, but
never replaces it (the server remains the authority):
- `id.trim() === ''` → `errors.id = 'Watch ID is required.'`
- `kind === 'facility' && parkName.trim() === ''` → `errors.parkName = 'Campground name is required.'`
- `kind === 'area' && areas.length === 0` → `errors.areas = 'Add at least one Recreation Area.'`
- `start === '' || end === ''` → `errors.dates = 'Both dates are required.'`
- `start >= end` → `errors.dates = 'Check-out must be after check-in.'` (plain string comparison is
  correct and timezone-safe for `YYYY-MM-DD`)

Render each error as `<p className="field-error">` directly under its field.

**`handleSubmit`:** `e.preventDefault()`, run `validate()`, bail if non-empty, then assemble and
call `onSubmit`:
```tsx
const dateRange = { start, end };
const watch: Watch = kind === 'facility'
  ? { type: 'facility', id: id.trim(), parkName: parkName.trim(), dateRange, siteType }
  : { type: 'area', id: id.trim(), areas: areas.map((a) => ({ name: a.name, recAreaId: a.recAreaId })), dateRange, siteType };
onSubmit(watch);
```
Only the area **criteria** are submitted. The `AreaPreview`'s resolved campground list is never read
here and never becomes part of the payload — `watches.json` stores criteria, the poller resolves them
fresh every cycle (ARCHITECTURE.md Anti-Pattern 1).

Do not add `react-hook-form`. Plain `useState` covers this form; the project's four-dependency
posture holds.

```tsx
async function handleSave(watch: Watch) {
  setBusy(true);
  setFormError(null);
  const isEdit = editing !== null;
  const url = isEdit ? `/api/watches/${encodeURIComponent(editing.id)}` : '/api/watches';
  try {
    const res = await fetch(url, {
      method: isEdit ? 'PATCH' : 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(watch),
    });
    const body = (await res.json().catch(() => ({}))) as { ok?: boolean; error?: string };
    if (res.ok && body.ok) {
      setWatches((prev) =>
        isEdit ? prev.map((w) => (w.id === editing.id ? watch : w)) : [...prev, watch]
      );
      setFormOpen(false);
      setEditing(null);
      setToast(COPY.savedToast);
    } else if (res.status === 401) {
      setUnlocked(false);
      setFormOpen(false);
      setError(COPY.unlockHeading);
    } else {
      // Modal STAYS OPEN with the reason visible: closing it would discard everything the user
      // typed on a recoverable failure like a duplicate id (409) or a validation error (400).
      setFormError(COPY.saveFailed.replace('{reason}', body.error ?? ''));
    }
  } catch {
    setFormError(COPY.saveFailed.replace('{reason}', ''));
  } finally {
    setBusy(false);
  }
}
```

Key behaviors, all load-bearing:

- The local list is updated in place rather than calling `router.refresh()`, for the same reason
  documented in this file's header: `page.tsx` reads through a 30s Data Cache window on

- A 401 mid-session flips the UI back to locked (the ~30-day cookie does expire).
- Every user-visible string still comes from `COPY`; the only inline literals are the `✎` and `×`
  glyphs and the `·` separator.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Form draft state → `/api/watches` | Untrusted, user-authored watch objects enter the persisted-config domain |
| Original watch id → URL path segment | `/api/watches/{id}` interpolation on edit |
| Client validation → server validation | The client check is UX; the server check is the control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-28 | Tampering | client-side validation bypass | mitigate | `validate()` in the form is convenience only; `parseStrictWatch` runs server-side on every POST/PATCH (plan 05-01/05-03) and is the sole authority — a devtools-modified payload is rejected there |
| T-05-22 | Tampering | watch id in the PATCH URL | mitigate | `encodeURIComponent(editing.id)` so an id containing `/` or `..` cannot escape its path segment |
| T-05-29 | Tampering | frozen area expansion leaking into the payload | mitigate | `handleSubmit` builds `areas` exclusively from the chip array; the `AreaPreview` result is never read by the form and never referenced in the submitted object (ARCHITECTURE.md Anti-Pattern 1) |
| T-05-30 | Information Disclosure | server error strings rendered in the modal | mitigate | The API's error bodies are already one safe line by construction (plan 05-03, T-05-16); they render as React text nodes, and no stack trace or GitHub response body is ever produced to render |
| T-05-24 | Elevation of Privilege | `unlocked` toggled in devtools to reveal Add/Edit | accept | Revealing the buttons changes nothing: every request they fire is rejected by `proxy.ts` plus each handler's own `requireSession()`. The client flag is an affordance, never an authorization decision |
</threat_model>
